# Super Agent Work Modes

Hall of Fame Studio now exposes five professional work modes through `GET /work-modes` and `POST /work-modes/:mode/team`:

- `learning`: learning plan, practice set, mastery check, academic-integrity escalation.
- `academic-writing`: outline, claim-citation graph, revision lineage, unsupported-claim escalation.
- `investigation`: hypotheses, source custody, contradiction matrix, evidence-bound claim escalation.
- `technical-delivery`: implementation plan, test evidence, rollback plan, security-release escalation.
- `creative-studio`: creative brief, critique log, rights/provenance register, licensing escalation.

The team composer uses the existing Hall of Fame persona capability map. It selects distinct people only when their relevant professional-skill score is at least 70; a missing specialist is returned as a coverage gap, not silently replaced with a generic agent.

Each composition is a kickoff contract. It assigns each required artifact to an execution owner and a distinct reviewer, generates a dependency DAG, and assigns every escalation check to the lead for an explicit decision when it is triggered. Custom role dependencies are accepted only when they reference known roles and remain acyclic; a cycle or invalid reference returns a blocked contract and `/projects/initiate` rejects it with `422`.

The resulting project tasks retain `dependsOn` and `reviewerId`, so the same ownership and review separation survives beyond the kickoff response. A caller may customize the text of a required artifact task, but cannot override its contract-assigned owner, reviewer, or prerequisites. The backend enforces those fields for work-mode tasks: only the assigned owner can submit, all prerequisite task submissions must already be accepted, and only the assigned independent reviewer can record acceptance. This is a local, self-hosted coordination guardrail; it makes no cloud dependency or public-production claim.

`npm run agents:work-modes:acceptance` exercises all five modes through the real backend contract. It creates each mode, submits every required artifact in dependency order, records the assigned independent review, confirms that unresolved escalation checks block acceptance, resolves those checks through the audited backend command, and verifies the final mode-specific acceptance result.

`POST /projects/:projectId/work-mode-escalations/:escalationId/resolve` is the only normal backend path for clearing a mode escalation. It requires the contract-assigned escalation owner, writes a timeline/event receipt, and is idempotent. The local artifact allowlist explicitly includes the required learning, academic-writing, investigation, technical-delivery, and creative-studio artifact types; unknown artifact types still do not become arbitrary persisted classifications.

Learning mode now has an executable local program beyond its three required submission artifacts. `GET /projects/:projectId/learning-program` returns `local-learning-program/v1`; plan creation and optimistic revisions use `/learning-program/plans`, while scored practice evidence uses `/learning-program/attempts`. Topic prerequisites are acyclic, pacing feasibility and shortfall are explicit, learner blackout dates are respected, compatible practice survives pace-only revision, and mastery requires three recent hint-free passing attempts before dependent topics unlock. Raw answer text is rejected from practice receipts. `npm run agents:learning-program` proves the diagnostic-to-mastery-to-spaced-review path across restart without an LMS or cloud profile.

Academic-writing mode now has an executable private pipeline at `GET /projects/:projectId/academic-writing-pipeline`. Versioned blueprints hash the research question and claim statements while retaining an acyclic section graph and references to real local evidence receipts. Drafts and revisions bind immutable `academic-manuscript` submissions, independent changes-requested and accepted reviews, stable issue ids, full issue resolution, coverage, and final lineage without copying manuscript content into pipeline receipts. `npm run agents:academic-writing-pipeline` proves the evidence-to-finalization path across file restart; its terminal state explicitly waits for capability 44 citation-integrity review.

Citation integrity is executable at `GET /projects/:projectId/citation-integrity`, with assessment and audit writes under the same route. The reviewer assesses every exact claim/source pair against an existing source snapshot; the receipt stores only closed judgements, dates, locator metadata, hashes/lengths, version lineage, and checksums. The audit blocks incomplete support, contradiction, irrelevant/uncertain use, stale publication or status checks, and corrected/retracted/unavailable sources. Only a valid audit for the exact frozen manuscript changes the academic pipeline to `citation-integrity-passed`; public-production readiness stays false.

Investigation mode now has a private executable case workflow at `GET /projects/:projectId/investigation-case`. Case versions retain hashed scope, competing hypothesis and falsification metadata; evidence rows bind actual source snapshots and approved source reviews before recording deterministic reliability and hypothesis relations. Case-specific custody events are append-only through independent seal, contradictions are derived rather than manually hidden, conclusion confidence is computed from evidence weights, and only the risk reviewer can freeze the exact conclusion. Closed cases reject later mutation while historical idempotent replay remains stable. `npm run agents:investigation-case` proves the workflow across file restart without claiming legal custody or adjudicative truth.

Investigation safety is mandatory at `GET /projects/:projectId/investigation-safety`. Policy/evaluation/resolution routes produce content-minimized authority, privacy, minimization, evidence-sufficiency, human-review, and one-time-use receipts. Investigation evidence, conclusion, and closure writes require an unexpired unused decision for the exact action/target and commit its use atomically with the business receipt. Hard prohibited or externally effective operations cannot be authorized by this local layer, and human resolution requires re-evaluation rather than flipping the original decision.

Technical-delivery mode now has an executable release-evidence workflow at `GET /projects/:projectId/technical-delivery-workflow`. A versioned plan binds unique requirements and acceptance criteria to affected paths, risk, and concrete rollback triggers/steps/verification. Verification binds one exact implementation revision, complete requirement evidence, passed tests, a passed rollback rehearsal, and security evidence for medium/high risk. Only the assigned independent quality/security reviewer can approve that exact revision with no blocking findings, and only then can the assigned product owner record a unique local package/service/workspace release receipt. Restart, stale links, duplicate target versions, time regression, or checksum tampering fail closed; this records a local release decision and does not execute a cloud deployment.

Engineering security is mandatory at `GET /projects/:projectId/engineering-security`. Every scan binds dependency, secret, permission, and static-analysis results to the exact implementation revision, with tool/config/evidence provenance and content-safe finding locations. Scan errors, missing or stale evidence, and unresolved findings block attestation. High/critical findings require remediation or independent false-positive review; secret findings can never be risk-accepted; low/medium exceptions require separate security-reviewer and product-owner approvals and expire within 30 days. The resulting 60-minute attestation binds the current governance manifest, and the technical-delivery release route rejects a missing, stale, expired, mismatched, or tampered attestation. This local ledger ingests scanner evidence; it does not execute a scanner or publish a cloud release.

Creative-studio mode now has an executable private workflow at `GET /projects/:projectId/creative-studio-workflow`. Versioned briefs bind real audience evidence to content-minimized direction, constraints, success criteria, and exact export specs. Iterations bind immutable stored `creative-work` submissions from the assigned art director. Creative-lead and audience-researcher critiques independently score four fixed dimensions, derive stable issue ids, and require complete issue closure in a newer artifact before revision. Dual approval gates exact deliverable export checks, followed by an editable-source/toolchain/dependency handoff and creative-lead acknowledgement. That exact terminal package is then consumed by capability 50 rather than being treated as externally releasable by itself.

Rights and provenance is executable at `GET /projects/:projectId/rights-provenance`. Asset declarations cover every current export output, editable source, and handoff dependency with rights basis, license evidence, permitted use/channel/territory, expiration, and attribution proof. Generated assets add content-minimized provider/model/policy, prompt hash, disclosure, evidence, and declared-input receipts; derivatives add an acyclic input lineage. The assigned rights reviewer cannot supply a verdict: the final audit derives findings and clears only the exact latest export, handoff, and acknowledgement for a bounded period. Declaration amendments are checksum-linked and historical evidence remains auditable. This is pure-local evidence governance, not legal advice or automatic public publishing authority.

Every learning guidance request can now pass through `POST /projects/:projectId/teaching-safety/evaluate` before teaching content is generated. `local-teaching-safety-decision/v1` stores no prompt or answer text and cannot be caller-downgraded: assessment answers, cheating concealment, child PII, and urgent wellbeing signals are hard stops; assignment answer review requires a real same-learner attempt receipt; external facts require a completed source-safe evidence record; authorized explanations require uncertainty disclosure and citations when applicable. `GET /teaching-safety` exposes policy, decisions, open human escalations, resolutions, and integrity. Human resolution records handling evidence but never authorizes the originally blocked answer.
