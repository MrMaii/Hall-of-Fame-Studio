# Independent Agent User-First README Workflow

Status: required companion to the Hall of Fame Studio Independent Agent Release Standard.

## 一句话定义

README 先帮普通用户在一分钟内看懂、安装、确认可用；完成这次友好沟通后，再呈现 Agent 的方法、证据、架构、质量门禁和资格边界。

The README first helps a normal user understand, install, and verify the Agent in one minute. Only then does it present method, evidence, architecture, quality gates, and qualification boundaries.

## 用户旅程

每个独立 Agent 的 README 必须遵循同一条路径：

```text
Recognize -> Watch -> Paste -> Verify -> First use -> Understand -> Audit
认出是谁 -> 看懂怎么装 -> 粘贴一句话 -> 确认可用 -> 第一次使用 -> 理解能力 -> 审核专业细节
```

### 1. Recognize / 认出

- 只显示 Agent 名称和语言入口。
- 顶部不堆徽章、长介绍、人物海报或技术状态表。
- 用户在三秒内知道“这是谁的 Agent”。

### 2. Watch / 看懂

- 紧接标题展示 `assets/install.gif`。
- 动图采用 Editorial Prompt：暖纸色背景、编辑感衬线标题、等宽安装指令、古铜色细线。
- 动画展示兼容 Agent 的平滑轮播、指令粘贴、`INSPECT -> MATCH -> INSTALL -> READY` 状态。
- 第一帧必须已经包含完整指令和 READY 结果；禁用动画时仍然有用。
- 动图说明安装流程，不模拟人物对话，不与 Archive Plate 争夺人物视觉身份。

### 3. Paste / 粘贴

动图下方立即提供可复制的一句话：

```text
Install <owner>/<repository> as a user-level Agent Skill for this agent. Inspect it first, use the matching host, and verify it is available.
```

这句话面向用户正在使用的通用 Agent。不得写成只适用于 Codex 的产品入口。

### 4. Verify / 确认

聊天安装是主路径；确定性 CLI 是紧随其后的备用路径：

```bash
gh skill preview <owner>/<repository> <agent-slug>
gh skill install <owner>/<repository> <agent-slug> --agent <host> --scope user
```

README 必须说明：重新打开或新建一次聊天，再确认 Skill 可用。发布验证不能只检查命令退出码；隔离安装目录中必须同时存在 wrapper `SKILL.md`、`agent/RUNTIME.md`、`agent/AGENT.md` 和硬 Skills。

### 5. First use / 第一次使用

- 给一个能直接粘贴的任务提示。
- 示例必须体现该 Agent 的独特判断方法，而不是人物模仿或传记问答。
- 普通对话默认保持轻量；只有明确任务才路由到相关硬 Skill。

### 6. Boundary / 边界

首屏末尾只保留一行清晰状态：repository-prequalified、是否经过 Director qualification，以及身份/背书边界。详细边界放在后文。

### 7. Understand and Audit / 理解与审核

完成用户友好沟通后，依次提供：

1. operating promise；
2. capability clusters 与输入/输出/停止条件；
3. evidence trace 与 source fingerprint；
4. conversation/task mode router；
5. quality loop；
6. 每张架构图恰好一次；
7. Archive Plate 恰好一次，作为人物身份与发布视觉；
8. Hall of Fame Studio 关系；
9. 完整资格、身份、隐私、金融/医疗/法律和实时事实边界；
10. 验证、贡献、许可和引用。

## 仓库与生成物

```text
agent/                              # standalone canonical release package
skills/<agent-slug>/SKILL.md        # discoverable installation entry
skills/<agent-slug>/agent/**        # generated byte-equivalent distribution
scripts/build-install-bundle.mjs    # canonical -> distribution sync
assets/install-motion.json          # Agent-specific motion copy only
scripts/build-install-gif.py        # shared deterministic renderer
assets/install.gif                  # README installation motion
```

`agent/` 是独立仓库内的发布主包；`skills/<agent-slug>/agent/` 只能由脚本生成。作者不得在两处分别修改人格、runtime 或 hard Skills。Studio 中的 authored source 仍然是最终来源。

## 每个 Agent 只允许改变的动图内容

- `agent_name`
- 两行 `headline`
- 一句 `promise`
- `repository`
- `skill_name`

动效节奏、尺寸、色板、字体层级、host 轮播、安装状态和第一帧回退保持统一。这样形成系列感，同时让人物能力承诺保持独特。

## 发布门禁

每次发布至少执行：

```bash
npm run bundle:build
npm run media:build
npm run validate
npm run fingerprint
npm run check:response
npm test
gh skill publish --dry-run
gh skill preview <owner>/<repository> <agent-slug>
gh skill install <owner>/<repository> <agent-slug> --agent <representative-host> --scope user
git diff --check
```

此外必须验证：

- canonical/distribution 文件集合和 SHA-256 完全一致；
- GIF 为 `960x640`、多帧、无限循环、第一帧完整可读；
- 英文和中文 README 的安装动图、一句话、CLI、首次使用和资格边界出现在专业分析之前；
- Archive Plate、每张架构图和安装动图各出现一次；
- 公共仓库 README、commit、tag/release 和安装命令从远端重新验证；
- handoff 报告 GitHub、release、skill name、fingerprint、测试证据以及仍需 Director qualification 的边界。

## 失败即停止

以下任一情况不得公开发布：安装目录不完整、分发副本漂移、动图不可重建、README 仍只写某一个 host、资格状态被夸大、Studio 名称错误、存在无关脏文件会被带入提交，或远端目标不明确。
